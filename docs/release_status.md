# Workflow status and required experiment artifacts

The current source connects prepared inputs, run configurations, structured
predictions, canonical evaluation and patient-paired five-seed statistics.
It does not bundle a complete executed experiment.

| Stage | Available implementation | Required external inputs / remaining integration |
| --- | --- | --- |
| CT volumes to prepared three-phase inputs | Prepared-image and annotation validators | Dataset access, series/position selection, phase correspondence, preprocessing implementation and provenance |

| RL | RARS, SHAE, curriculum components, launcher and version-restricted VeRL patches | Compatible distributed runtime and a verified real training execution |
| RARS OAT | Explicit profiles, task plan and validation collector | Completed training/prediction receipts for every required profile and seed; subsequent combined-profile training |

## Changes that affect reruns

- Detector export now separates fitting and validation by default. Use a new
  output directory and the intended original partition policy. Previously
  trained models cannot be assigned a different training population retroactively.
- Logprob integration rejects missing or nonfinite values at valid response
  tokens. Padding alone may be filled with zeros. A run that previously used
  substituted valid-token logprobs needs its reward/training inputs reviewed.
- Inference uses unprocessed model logits and includes the generated EOS token
  in the single-sequence completion NLL. This can change a patient tie relative
  to older outputs computed from processed scores or an omitted EOS. Regenerate
  and reevaluate affected predictions.
- Joint statistics requires per-patient, per-seed exports. Cohort means and SDs
  cannot supply the missing pairing. Rerun the evaluator on saved original
  predictions before applying the new statistics tool.

SHAE normalization, RARS reward terms and the visual feature recipe have not
been replaced by a different algorithm in this maintenance change. In
particular, low-dispersion SHAE behavior and rewards for unmatched predictions
need real-run stability/behavior measurements when assessing the method. A
change to those formulas or features is a new training experiment.

## Verification record

The repository tests use synthetic data and CPU tensors. Source-patch tests
check supported source layouts; integration tests needing external VeRL source
skip when that source is absent. Model stubs check inference/control flow and
NLL calculations. Configuration tests check generated SFT commands, not actual
multi-GPU execution. Exact small-population enumeration checks the statistical
resampling implementation.

For a result release, retain the code commit, environment versions, model and
input identities, split/phase manifests, per-run configurations, checkpoint
identities, raw completions, evaluation exports and the comparison specification.
File hashes make subsequent file changes detectable; the originating run records
supply provenance. No clinical performance values are generated by these tests.
